# Contributing to 8x8 OS

Contributions are welcome in documentation, tests, examples, security, connectors, agent coordination, memory, observability, Studio workflows, and Web3 modules.

## Before opening a pull request

1. Open or reference a focused issue.
2. State whether the work is implementation, experiment, specification, or roadmap.
3. Keep secrets and private runtime data out of commits.
4. Include tests or reproducible verification steps.
5. Document limitations and failure behavior.
6. Avoid claims that exceed the evidence in the pull request.

## Pull-request checklist

- [ ] Scope is clear and bounded
- [ ] No credentials, personal data, or unsafe internal details
- [ ] Tests or manual verification included
- [ ] Documentation updated
- [ ] Security impact considered
- [ ] Backward compatibility considered
- [ ] Capability status label is accurate

## Design principles

- Human authority over consequential actions
- Observable and auditable execution
- Explicit permissions and bounded autonomy
- Replaceable components and documented interfaces
- Fail-closed safety behavior
- Honest separation of implemented, experimental, and planned work

## Areas needing help

- Reproducible demos and test harnesses
- Threat modeling and security review
- Agent and connector SDK design
- Cross-platform packaging
- Documentation and diagrams
- Accessibility and user experience
- Observability and receipt verification
