# Public 8x8 V1 Scope

## Purpose

`integration/public-8x8-v1` is the single convergence lane for the public-safe 8x8 product. It extends the protected beta without exposing the private owner runtime.

## Product model

Public 8x8 V1 presents three monitors and three realities:

1. **Monitor 1 — Public Present:** deployed, tested, public-safe capabilities.
2. **Monitor 2 — Private Owner Boundary:** an explicit boundary showing what is not mounted publicly.
3. **Monitor 3 — Future Lab:** research, simulations, release candidates, and modernization plans that are clearly separated from live claims.

Private Past is recovered and classified behind the scenes. Public Present receives only sanitized, compatible, receipted release units.

## Included in V1

- Whole-system architecture and evidence map
- Public product portal and route registry
- Public-safe agent and council identities
- Bounded mission drafting and mission-status views
- Studio and Visual Council artifact provenance
- World, Art Board, Future Lab, and accessible public clients
- Connector authority and freshness summaries without secrets
- Testnet blockchain and synthetic market intelligence
- Release receipts, exact-head deployment status, and rollback metadata

## Excluded from V1

- Owner terminal or shell access
- Private memory, raw messages, credentials, secrets, or precise topology
- Live wallets, mainnet signing, payments, or trading execution
- Production database mutation
- Unrestricted agent execution or authority inheritance
- Unsupported compliance, revenue, uptime, quantum, or completion claims

## Integration rule

Every public capability must have one canonical ID, implementation source, truth label, maturity state, dependency list, test set, last verified commit, public/private classification, and rollback path.

## Promotion gate

A release unit may move into Public Present only when all applicable gates pass:

1. Identity and authority resolved
2. Scope and truth labels declared
3. Implementation complete
4. Exact-head tests pass
5. Security, privacy, rights, provenance, and accessibility pass
6. Compatibility and rollback proven
7. Source and artifact digests recorded
8. Deployment succeeds
9. Root and changed routes return expected responses
10. Estate registry and product map are updated

## Compatibility

The current protected beta remains the rollback baseline. Existing routes and older workflows stay available until the integration lane proves parity or documents an intentional replacement.

## Completion language

A release unit may score complete inside its declared scope. It must never imply that the private runtime, entire estate, continuous autonomy, or whole-system build is complete.
