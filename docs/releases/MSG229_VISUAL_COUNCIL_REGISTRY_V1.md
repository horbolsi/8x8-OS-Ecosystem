# MSG229 Visual Council Registry V1

## Purpose

Create one evidence-backed public-safe registry for the four current 8x8 vision images and establish the submission contract for future agent and subagent visual work.

## Truth boundary

The images are vision artifacts. They are not live dashboards and must not be interpreted as proof of live users, model counts, health percentages, global reach, wallet activity, production autonomy or whole-system completion.

The release unit scores 100/100 only inside the declared registry scope:

- four supplied binaries have unique SHA-256 digests;
- dimensions and byte sizes are recorded;
- owner-session authorship is recorded;
- Drive evidence references are present;
- one weighted rubric is applied consistently;
- limitations and non-live status are explicit;
- the 123+ agent submission contract is defined;
- public boundary and accessibility tests are included.

Whole-system completion remains `NOT_INFERRED`.

## Agent and subagent fleet

A visual may be attributed to an agent only when the submission includes:

- canonical agent ID and name;
- body ID and role;
- prompt digest and source-context digest;
- model or creation tool;
- creation timestamp;
- binary SHA-256 and dimensions;
- license and provenance;
- self-score, council score and truthfulness score;
- differences from the canonical reference;
- gaps or contradictions detected.

Existing Drive and Canva visuals without those receipts remain `UNATTRIBUTED` rather than being assigned to Hermes, Claude, Seraphim, Jarvis or another identity by guesswork.

## Three realities operating model

### Private Past

Inventory dormant code, mixed folders, historical contexts, receipts, experiments, models, bodies, scripts and connector state. Never publish secrets or precise private topology.

### Public Present

Promote independently complete, public-safe release units after exact-head CI, accessibility, privacy, provenance, boundary verification, deployed-route checks and rollback evidence.

### Future Lab

Generate competing visions, simulations, 360 agent bodies, videos, presentations, playable worlds and new-power proposals. Council disagreement is preserved as evidence and used to detect memory drift, isolated shells and incomplete integration.

## Continuous content architecture

Future media production must be bounded by a content receipt containing:

- content ID and parent mission;
- agent and body IDs;
- source citations and rights state;
- prompt/context hashes;
- output binary hashes;
- accessibility artifacts such as captions, transcript and alt text;
- safety and public/private classification;
- council review and owner gate;
- publication target and rollback/removal path;
- performance and engagement measurements after release.

This contract applies to images, charts, GIFs, avatars, voice, videos, presentations, introductions, explanations, documentation and community replies.
